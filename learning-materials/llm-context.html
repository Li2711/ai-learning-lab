  2. 为什么对话开头的约定，聊到后面会被"忘掉"？
  3. 上下文越长越好吗？长上下文有哪些代价和陷阱？

草稿：上下文就是模型在生成回答那一刻"摊在桌面上"的全部材料——系统提示、当前对话历史、工具返回的结果、检索到的文档等，全部拼成一个文本序列送给模型。上下文窗口是这份材料的空间上限，以 token 计量。最关键的一点：模型本身没有记忆，"多轮对话"其实是把前面的聊天记录反复重新塞给它。所以它"记得"还是"忘了"，取决于你有没有把相关信息放进这一次的窗口里。

四、核心机制 / 组成

上下文窗口里通常装着什么

┌────────────── 上下文窗口（以 token 计数）──────────────┐ │ ① 系统提示（System Prompt）—— 角色设定、规则、Skill 指令 │ │ ② 对话历史 —— 用户和模型历往的消息（多轮对话的本质） │ │ ③ 工具结果 / 检索文档（RAG）—— 外部世界的真实信息 │ │ ④ 当前用户消息 —— 本次要处理的新输入 │ │ ⑤ 模型即将生成的回答（预留输出空间） │ └──────────────────────────────────────────────┘

关键机制

  • Token 计量：文本被切成 token（约 1 个汉字 ≈ 1~2 个 token），窗口大小如 128K、200K 指可容纳的 token 总量，输入+输出共享这个额度。
  • 无状态调用：每次请求都是独立的，"记忆"完全靠把历史重放进上下文实现；对话过长时被截断或压缩，早期的约定就丢了。
  • 注意力并非均匀：论文《Lost in the Middle》用实验证明——关键信息放在上下文的开头或结尾时模型表现最好，埋在长上下文中间时性能明显下降，即使是很长的上下文模型也一样。

五、具体应用场景：为什么"改新文件"之前要先开新会话

场景：我先用 AI 调试了一个上午的程序 A，对话里满是报错和废弃方案。下午想让它帮我写作业报告 B。

  1. 问题出现：在同一个会话里直接问"帮我写报告 B"，模型写出来的东西带有一上午调试的"口音"——因为它还背着几千 token 的旧上下文（系统提示、旧代码、旧结论），注意力被无关信息稀释。
  2. 改进做法：开新会话，只把写 B 需要的材料（作业要求、自己的代码要点）一次性放进上下文，相当于做了一次"上下文工程"：精心决定窗口里装什么、不装什么。
  3. 对应到 Agent：Agent 的每一步工具结果都会写进上下文，任务越长窗口越满，所以成熟 Agent 系统要做"压缩 / 摘要 / 把长结果写入外部文件"等管理手段——这正是 Anthropic《Effective Context Engineering》强调的"上下文是 Agent 最稀缺的资源"。

六、容易混淆的问题 / 使用边界

最易混淆的两组概念

易混淆区分
上下文窗口 vs 训练数据窗口是"这次请求能看的材料"，随对话变化；训练数据是"模型出厂前学过的知识"，固定不变。模型答不出最新事件，常是因为信息不在窗口里，而不是模型"不会"。
上下文 vs 记忆严格说模型没有跨请求记忆；产品里的"记忆"功能（如保存偏好）本质是把历史信息检索出来、重新放进上下文的工程机制。
上下文工程 vs 提示词工程提示词工程偏向"怎么措辞一句话"；上下文工程是"决定窗口里放哪些信息"（提示、示例、检索结果、工具输出、状态历史），覆盖面更大，也更贴近实际系统开发。

使用边界

  • 窗口大 ≠ 能用好：不要因为支持 200K 就把所有资料一股脑塞进去——"lost in the middle"效应说明中间位置的信息利用率会下降，塞太多还提高成本和延迟。
  • 窗口内 ≠ 都准确：放进上下文的错误信息会被模型当作事实采信（垃圾进、垃圾出），核查信息质量仍不可省略。

七、自测问题

题 1（概念辨析）：用户说"模型总是忘了我第一句话的要求"。从上下文机制出发，给出两种可能原因。

参考要点：① 对话太长，早期消息被截断或压缩，不在当前窗口里；② 信息还在窗口里但处于"中间位置"，注意力利用不充分（lost in the middle）。对策：把关键要求写进系统提示或每次消息末尾（位置效应），或开新会话重建精简上下文。

题 2（应用）：你要让 AI 基于 3 份 PDF 写综述，怎么设计上下文能提高准确率？

参考要点：不整本塞入，先用检索（RAG）定位相关段落；关键结论放开头/结尾；给模型"只依据所给材料作答、引用出处"的约束，便于事后核查。

题 3（边界）：为什么"上下文里提供了 10 篇文档"不等于"模型能准确回答所有相关问题"？

参考要点：长上下文存在位置衰减（lost in the middle）；token 占满会挤掉输出空间并增加成本；无关信息会干扰判断。信息要"精而准"地放入窗口，而不是"多而全"。
