上下文 × Agent × Skill

文字版与 Mermaid 图见同目录 concept-relationship.md · 生成后经人工核查 · 2026-09-09

一句话关系

上下文是资源，Agent 是消耗资源完成任务的系统，Skill 是往资源里"精装"可复用知识的机制。

三者关系图

上下文如何影响 Agent（重点一）

  • 知道什么：Agent 只能基于窗口内容决策，关键信息不在窗口里 = 失明。
  • 能干多久：窗口有限，长任务靠压缩/外部化信息维持目标不丢失。
  • 干得多准：Lost in the Middle 效应——关键内容放开头或结尾，剔除无关信息。

Skill 如何沉淀知识（重点二）

  • 把"每次都要重新交代的要求"写成 SKILL.md，写一次、处处复用。
  • 元数据常驻（几十 token），正文按需加载——对上下文稀缺的直接回应。
  • Agent 提供自主执行力，Skill 提供固定流程与自检，二者互补。

个人判断

我的判断是：这三个概念其实是同一件事的三个层次——上下文回答"信息从哪来"，Agent 回答"怎么持续行动"，Skill 回答"经验怎么不流失"。它们之间有依赖顺序：不理解上下文是有上限的资源，就看不出 Skill 为什么要做成渐进式加载；不理解 Agent 会自主决定步骤，就看不出 Skill 里为什么必须写自检和边界。

最反直觉的一点是：上下文不是"越大越好"的免费资源，它更像内存——塞什么、先塞什么、什么时候清掉，都要设计。想明白这一点后，我再看那些复杂的 Agent 框架，会发现它们很大一部分工作其实都在做同一件事：管好那张"桌面"。而 Skill 就是往桌面上放东西的一种最省地方的写法：平时几乎不占位置，需要时才翻开。
