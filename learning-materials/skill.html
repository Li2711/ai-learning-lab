三、个人解释

草稿：Skill 是给 AI 用的"作业手册"。它是一个放在约定目录里的文件夹，核心是一个 SKILL.md：开头几行 YAML 元数据（name、description）像书的封面和索引，让 AI 知道"这里有个什么技能、什么时候用"；正文则是完成任务的具体步骤、规则和注意事项。妙处在于平时只占几个 token 的元数据常驻上下文，正文只在任务匹配时才被加载——像图书馆的书平时在架上，要用才翻开。对个人来说，Skill 的价值是把"每次都要重新交代的经验"变成"写一次、处处可用"的资产，就像把老师傅的手艺写成操作规程。

四、核心机制 / 组成

最小组成结构

my-skill/
└── SKILL.md        ← 必需：YAML 元数据 + Markdown 正文
（可选）scripts/     ← 可执行脚本
（可选）references/  ← 详细参考文档
（可选）assets/      ← 模板、素材文件

SKILL.md 的两段式结构

---
name: concept-study-guide          ← 唯一标识（小写、连字符）
description: 输入概念输出结构化学习资料… ← 决定 AI 何时启用本技能
---

# 正文：适用场景、输入、步骤、输出结构、自检…

渐进式加载（三层）

层级何时进入上下文占用 token
① 元数据（name + description）会话开始就常驻很小（几十）
② SKILL.md 正文任务匹配 description 时加载中
③ 附属文件（脚本/参考文档）正文引用、需要时才读按需

这个机制解释了 Skill 与"把所有提示词都塞进系统提示"的区别：后者常驻占满上下文，前者按需取用。多个 Skill 的元数据可以共存，AI 依任务挑选加载。

五、具体应用场景：本仓库的 concept-study-guide

本仓库 .workbuddy/skills/concept-study-guide/SKILL.md 就是一个正在运行的真实例子：

  1. 沉淀：把"怎么生成一份合格的概念学习资料"的经验写成固定流程——九节结构、来源核验规则、自检清单（见本仓库 Skill 文件）。
  2. 触发：在 WorkBuddy 中说"用 concept-study-guide 学习 MCP"→ AI 匹配 description → 加载 SKILL.md 正文。
  3. 执行：AI 按固定步骤检索来源 → 核验链接 → 按九节结构生成 learning-materials/mcp.html → 执行自检。
  4. 复用：换任何新概念（如"RAG""微调"）重复步骤 2~4，产出格式一致、质量稳定的资料——这就是"可复用"的含义。本仓库的 agent / llm-context / skill 三份资料即由该 Skill 的流程生成。

六、容易混淆的问题 / 使用边界

最易混淆：Skill vs 工具（Tool）vs MCP

SkillTool / MCP
本质知识：教 AI"怎么把事做好"的指令文档能力：让 AI"能做某事"的接口（执行代码、调 API）
形态文件夹 + Markdown，无代码也能写函数 / 服务器 / API
类比操作手册、菜谱厨具、水电网

常见误解

  • "Skill 是代码插件"：不一定是。最小 Skill 纯 Markdown 就能工作；脚本是可选增强。
  • "description 随便写"：错。description 是 AI 决定"何时启用本技能"的唯一依据，写得含糊会导致该用时不用、不该用时乱触发。

使用边界

  • 一次性任务不值得写 Skill：只有可重复、有稳定流程的任务才值得沉淀；写 Skill 本身有成本。
  • Skill 不是万能知识库：它提供流程和规范，不替代模型的基础知识，更不保证事实准确——这正是本 Skill 强制"来源核验 + 人工核查"的原因。

七、自测问题

题 1（概念辨析）：把"周报生成流程"同时做成了一段长系统提示和一个 Skill，后者有什么好处？

参考要点：① 省上下文——平时只有几十 token 的元数据常驻，正文按需加载；② 可复用可分享——独立文件夹可直接复制给他人或放进版本库；③ 可维护——改流程只动一个文件，不必重写系统提示。

题 2（应用）：你的 Skill 总是不被 AI 主动触发，最可能的原因是什么？怎么改？

参考要点：description 写得含糊或没写明触发场景。应把"做什么 + 何时用"写具体，包含用户会说出的关键词（如"生成概念学习资料""学习 XX 概念"）。

题 3（边界）：什么情况下不该把经验写成 Skill，直接用临时提示词更好？

参考要点：任务一次性、流程还在频繁试错、经验尚未稳定。Skill 适合沉淀已验证的稳定流程；过早固化会把试错成本写进文档，反而难以维护。
