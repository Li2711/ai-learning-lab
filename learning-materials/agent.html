一、学习目标

  1. 能用自己的话定义 Agent，并说清它与"直接调用一次大模型"的区别。
  2. 能画出 Agent 的基本循环（感知 → 规划 → 调用工具 → 观察 → 再行动）并解释每一环的作用。
  3. 能判断一个任务适不适合交给 Agent 做，说出至少两个"不该用 Agent"的边界情形。

二、核心问题

  1. Agent 和普通的大模型问答，本质区别到底是什么？
  2. Agent 靠什么"动手做事"？（工具调用是怎么发生的）
  3. Agent 的"自主性"是一把什么样的双刃剑？失控风险来自哪里？
  4. 为什么几乎所有教材都强调：能用固定流程（workflow）解决的事，就不要上 Agent？

草稿：Agent 是以大模型为"大脑"、以工具为"手脚"、以循环为"工作方式"的系统。普通调用大模型像问一个关在房间里的专家——只能靠嘴回答；Agent 则让这个专家可以走出门，自己去查资料、动手操作、看到结果后再决定下一步。它不是一个更聪明的模型，而是围绕模型搭起来的一套"感知—决策—行动—反馈"的工作循环，模型的输出（尤其是"调用工具"的输出）反过来变成系统的输入，直到任务完成。

四、核心机制 / 组成

Agent 通常由四个部分组成（参考 Lilian Weng 的经典拆解）：

组成角色比喻说明
LLM 核心大脑负责理解目标、拆解步骤、决定下一步动作
规划（Planning）做事的章法任务拆解、自我反思与修正（如 ReAct、CoT）
记忆（Memory）笔记本短期记忆是上下文里的对话/中间结果；长期记忆常靠外部存储检索
工具（Tool use）手脚通过函数调用（function calling）执行搜索、读写文件、调用 API 等

Agent 的典型运行循环：

接收目标 → LLM 思考并决定动作（输出想法 + 是否调用工具） → 执行工具，拿到真实结果（观察） → 结果写回上下文 → 循环，直到 LLM 判断任务完成或达到步数上限

Anthropic 在《Building Effective Agents》中把这类系统分为两档：workflow（开发者预先编排好固定流程，模型只是其中环节）和 agent（模型自己动态决定步骤和工具）。这个区分是判断"要不要上 Agent"的关键。

五、具体应用场景：帮我查三天后的会议该准备什么

假如对一个接入日历、邮件和搜索工具的 Agent 说："周五我要向导师汇报，帮我准备好材料清单。"

  1. 理解与规划：Agent 调用日历工具查到周五 14:00 的汇报日程，发现距今天 3 天。
  2. 收集信息：调用邮件工具找到导师上周发的"汇报要求"邮件，提取出需要的 3 项内容（实验结果、参考文献、时间表）。
  3. 行动：检查本地文档工具，发现实验结果已有、文献缺 2 篇 → 调用搜索工具找到论文并存档。
  4. 反馈修正：发现时间表一周前的版本已过期，用最新实验进度重排时间表。
  5. 汇总：输出一份材料清单 + 已完成的准备 + 待你确认的两处改动。

这个任务没法在"一次问答"里完成——每一步都依赖上一步拿到的真实信息，这正是 Agent 适合的场景。

六、容易混淆的问题 / 使用边界

最易混淆：Agent vs Workflow vs Chatbot

Chatbot（普通问答）Workflow（固定流程）Agent（自主循环）
谁决定步骤人开发者预先编排模型在运行时自主决定
可预测性高高低（有失控与跑偏风险）
适用一次问答、改写、翻译步骤明确、量大、要稳定开放式任务、步骤无法预知

常见误解

  • "Agent = 更强的模型"：错。换更强模型不会自动获得自主性，Agent 是系统架构，不是模型能力。
  • "越自主越好"：错。Anthropic 明确建议——能用单一调用或 workflow 解决的就用简单方案，因为自主性伴随成本、延迟和错误累积风险。

使用边界（不该用 Agent 的情形）

  • 任务步骤固定且可预知（如每天固定格式抓取报表）→ 用 workflow，稳定又便宜。
  • 操作后果不可逆且高风险（直接执行支付、删库）→ 应加人工确认环节，甚至不给该工具。

七、自测问题

题 1（概念辨析）：一个"自动写周报"的程序，先查 Git 提交记录，再按固定模板生成周报。它是 Agent 吗？

参考要点：更接近 workflow。步骤固定（查记录→套模板），模型只在个别环节工作，开发者预先编排了全流程；Agent 的判断标准是"模型自主决定步骤与工具使用"，而不是"用了工具就是 Agent"。

题 2（应用）：你要让 Agent 完成"调研 5 篇论文并汇总成表"，应该在系统提示里给它哪些关键设定？

参考要点：可用工具清单（搜索、读文件、写文件）；明确的完成标准（表格字段、5 篇都覆盖）；步数上限防失控；要求关键结论附论文链接以便核查。

题 3（边界）：为什么给 Agent 接"直接执行删除数据库"这类高危工具要非常谨慎？

参考要点：Agent 的决策由概率模型做出，没有 100% 的正确率；错误会直接变成真实世界的不可逆后果。工程上应把高危操作设为"请求人工确认"，或压根不提供该工具（权限最小化）。
